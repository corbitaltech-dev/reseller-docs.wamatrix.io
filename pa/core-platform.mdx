**Core Platform** contains settings that apply to your platform and all tenants. You can configure AI, API access, notifications, and subscription lifecycle rules here.

## What you see on the screen

Click **Settings → System Settings** in the sidebar to open this page.

The settings are divided into eleven tabs. Some settings are covered in separate pages.

## AI

Your tenants use AI to write better chat replies, build automations faster, and answer customer questions automatically.

Using this setting, you choose how this AI runs: with the AI included in your WaMatrix plan, or with your own API key from an AI provider like OpenAI or Google Gemini. Your choice applies to every AI feature.

<Frame caption="The AI tab with My own API key selected">
  <img src="/images/pa/ai-configuration.png" alt="The AI tab with My own API key selected, showing this month's usage and the AI provider cards" />
</Frame>

### Choose your AI option

<Tabs>
  <Tab title="Platform tokens">
    Use the AI that comes with your WaMatrix plan. You don't need to set anything up.
  </Tab>
  <Tab title="My own API key">
    Use your own account with an AI provider, like OpenAI or Google Gemini. The AI provider bills you directly.

    <Steps>
      <Step title="Pick your AI provider">
        Click **OpenAI**, **Google Gemini**, **Anthropic** or **Groq**.
      </Step>
      <Step title="Paste your API key">
        An API key is a password from your AI provider's account. Paste it in the box. Click **Test** to check it works.
      </Step>
      <Step title="Pick a model and save">
        Choose a **Model**, then click **Save Changes**.
      </Step>
    </Steps>

    <Note>
      To use your own API key, your WaMatrix plan must include **Bring Your Own AI Key**. If it doesn't, the card shows an **Upgrade** badge. Click the card to upgrade your plan.
    </Note>
  </Tab>
</Tabs>

### Your AI limits

Your plan comes with two AI limits. They stay the same whether you use **Platform tokens** or **My own API key**.

| Limit | What it counts |
| ----- | -------------- |
| **AI Usage Tokens** | AI tokens used. Counts only on **Platform tokens**. |
| **AI API Calls** | AI API requests used. Counts on both **Platform tokens** and **My own API key**. |

<Warning>
  When **AI API Calls** runs out, all AI stops until next month — on **Platform tokens** and on **My own API key**.
</Warning>

To see how much you have used, check **Usage this month** on the AI tab. It shows the AI tokens and AI API requests used so far this month, against each limit.

### AI assistants and knowledge bases

An AI assistant answers questions from a **knowledge base** — the documents and websites your tenant added to it. Each knowledge base is saved in the AI provider account that was active when it was created.

So if you switch between **Platform tokens** and **My own API key**, or change AI provider, your AI assistants stop answering. Click **Re-index** to move them to the new account.

<Warning>
  **Re-index every time you switch your AI option or AI provider.** If you don't, your tenants' AI assistants stop replying to their customers.
</Warning>

<Steps>
  <Step title="Save first">
    Save your new choice. **Re-index** stays off until you save.
  </Step>
  <Step title="Click Re-index">
    This moves all AI assistants, for all your tenants.
  </Step>
  <Step title="Wait a few minutes">
    The page updates by itself. When you see **Up to date**, you are done.
  </Step>
</Steps>

| You see | What it means |
| ------- | ------------- |
| **Up to date** | All AI assistants are working. |
| **2 waiting** | Two AI assistants need a re-index. Click **Re-index**. |
| **Re-indexing** | The move is running. Please wait. |
| **Not supported** | Anthropic and Groq can't run AI assistants. Use OpenAI or Google Gemini. |

### Website reading

AI assistants can read website content and use it as a knowledge base. Browser-based reading can be enabled for websites that require JavaScript to load their content.

<Frame caption="The website reading settings, with the reader endpoint, page cap and test field">
  <img src="/images/pa/ai-website-reading.png" alt="The website reading settings, with the reader endpoint, page cap and test field" />
</Frame>

| Field | Description |
| ----- | ----------- |
| **Enable browser-based reading** | Enables browser-based website reading. |
| **Reader endpoint** | The service used to load and read website pages. |
| **Max pages per website** | Maximum number of pages to read from one website. |
| **API key (optional)** | API key for the reader service. Leave blank to use the free tier. |

<Tip>
  Use **Test it on a page** to check the configuration before using it.
</Tip>

<Note>
  These settings apply to all tenants. Tenants do not configure them separately.
</Note>

## API Keys

**API Keys** let your website read your plans, prices, and feature lists directly from the platform.

<Frame caption="The API Keys tab, with the base URL, endpoints, auth header, and the token list">
  <img src="/images/pa/api-keys.png" alt="The API Keys tab, with the base URL, endpoints, auth header, and the token list" />
</Frame>

The page shows the **Base URL**, available endpoints, and **Auth header**. Use the copy buttons to copy these values.

<Note>
  API tokens are read-only. They can read your plans, prices, and feature lists, but cannot change platform settings or access tenant data.
</Note>

### Create an API token

<Frame caption="The Add API Token panel, with the name, scopes, and expiration date fields">
  <img src="/images/pa/api-keys-add-token.png" alt="The Add API Token panel, with the name, scopes, and expiration date fields" />
</Frame>

<Steps>
  <Step title="Click Add Token">
    Opens the token creation panel.
  </Step>
  <Step title="Enter a name">
    Enter a name that identifies where the token will be used, such as **Marketing site**.
  </Step>
  <Step title="Select the scopes">
    Select the **Scopes** that the token is allowed to read.
  </Step>
  <Step title="Set an expiration date">
    **Expiration Date** is optional. Leave it empty if the token should not expire.
  </Step>
  <Step title="Create the token">
    <Warning>
      The token is shown **only once** after creation. Copy and store it securely. If you lose it, you must regenerate it. The old token will stop working.
    </Warning>
  </Step>
</Steps>

### Managing tokens

You can **Regenerate** or **Delete** each token.

**Regenerate** creates a new token and makes the old token stop working.

**Delete** permanently removes the token.

<Card title="Plan Catalogue API" icon="code" href="/api/overview" horizontal>
  Learn how to use the token to read your plans from your website.
</Card>

<Frame caption="The Alert Email Address field at the top of the Notification tab">

</Frame>

Set **Alert Email Address** to the email address where you want to receive alerts.

<Warning>
  No alerts are sent until you configure and save the notification settings.
</Warning>

<Tabs>
  <Tab title="Email Alerts">
    <Frame caption="The Email Alerts tab, with a switch for each event">

    </Frame>

    | Event | Sent when |
    | ----- | --------- |
    | **New Tenant Registered** | A new tenant registers. |
    | **Payment Failed** | A tenant's payment fails. |
    | **Subscription Expired** | A tenant's subscription expires. |
    | **Subscription Renewed** | A tenant renews their subscription. |
    | **Plan Changed** | A tenant changes their plan. |
    | **Tenant Suspended** | A tenant is suspended. |
    | **Tenant Reactivated** | A suspended tenant is restored. |
    | **Tenant Deactivated** | A tenant is marked inactive. |
    | **Subscription Cancelled** | A tenant cancels their subscription. |
    | **Tenant Deleted** | A tenant is deleted. |
    | **Offline Payment Submitted** | A tenant submits an offline payment request. |
    | **Plan Limit Almost Reached** | Your plan is close to reaching a feature limit. |
    | **Daily Summary Email** | A daily summary of tenant activity is sent. |

    For **Plan Limit Almost Reached**, you can set the warning percentage. The default is **80%**.

    <Note>
      **Plan Limit Almost Reached** applies to your plan, not tenant plans. Tenant plan limit alerts are configured under [Tenant Plan Limit Alerts](/pa/onboarding-a-sub-tenant#tenant-plan-limit-alerts).

  <Tab title="App Notifications">

    | Event | Shown when |
    | ----- | ---------- |
    | **New Tenant** | A new tenant registers. |
    | **Payment Completed** | A tenant's payment succeeds. |

    | **Plan Changed** | A tenant changes their plan. |
    | **Offline Payment Submitted** | A tenant submits an offline payment request. |
    | **Subscription Cancelled** | A tenant cancels their subscription. |

    | **Subscription Expired** | A tenant's subscription expires. |

    | **Facebook Lead Ads Token Revoked** | A Facebook Page token has been revoked. |

    The last three are technical alerts and appear only in the notification centre.

    <Warning>
      Keep **Analytics Snapshot Stale** enabled. Analytics that are not collected can be lost permanently after 7 days, and this notification is the only warning.
    </Warning>
  </Tab>
</Tabs>

## Subscription Lifecycle

**Subscription Lifecycle** controls what happens when a tenant's subscription expires or a payment fails.

<Info>
  These settings apply to **your tenants**, not your own subscription.
</Info>

### Grace Period & Suspension

<Frame caption="The Grace Period & Suspension card, with the grace period and billing-only days">
  <img src="/images/pa/lifecycle-grace-period.png" alt="The Grace Period & Suspension card, with the grace period and billing-only days" />
</Frame>

| Field | Description | Default |
| ----- | ----------- | ------- |
| **Grace Period (days)** | Days of full access after the subscription expires. Set to 0 to suspend immediately. | 3 |
| **Billing Only (days)** | Days the tenant can sign in and pay, but cannot use other features. | 3 |

After a subscription expires, the tenant moves through three stages:

<Steps>
  <Step title="Full access" icon="circle-check">
    The tenant keeps full access during the grace period.
  </Step>
  <Step title="Billing Only" icon="credit-card">
    The tenant can sign in and pay, but cannot use other features. Their data remains available.
  </Step>
  <Step title="Expired" icon="circle-x">
    The subscription has ended.
  </Step>
</Steps>

### Deletion Scheduling

<Frame caption="The Deletion Scheduling card, with the deletion delay in days">
  <img src="/images/pa/lifecycle-deletion-scheduling.png" alt="The Deletion Scheduling card, with the deletion delay in days" />
</Frame>

**Deletion Delay (days)** sets how long after an automatic suspension before the tenant's data is permanently deleted. The default is **14 days**.

This applies only to tenants suspended automatically by **Payment Retry**. Tenants suspended manually are not deleted automatically.

<Warning>
  Tenant data is permanently deleted after this period. Set a suitable delay so tenants have time to notice the suspension and make a payment.
</Warning>

### Auto-Renewal (eMandate)

These settings control Razorpay auto-renewal timing. An eMandate allows automatic charges from the tenant's bank account.

<Frame caption="The Auto-Renewal card, with the lead time and pre-debit wait">
  <img src="/images/pa/lifecycle-auto-renewal.png" alt="The Auto-Renewal card, with the lead time and pre-debit wait" />
</Frame>

| Field | Description | Default |
| ----- | ----------- | ------- |
| **Lead Time (days)** | Days before renewal when the renewal process starts. | 3 |
| **Pre-debit Wait (hours)** | Time between the pre-debit notice and the charge. | 24 |

<Warning>
  In India, the RBI requires **24 hours** between the pre-debit notice and the charge.
</Warning>

### Payment Retry (Dunning)

**Payment Retry** allows the platform to retry failed payments before suspending the tenant.

This applies only to tenants with auto-renewal and a saved payment method.

<Frame caption="The Payment Retry card, with the retry limit and the interval between attempts">
  <img src="/images/pa/lifecycle-dunning.png" alt="The Payment Retry card, with the retry limit and the interval between attempts" />
</Frame>

| Field | Description | Default |
| ----- | ----------- | ------- |
| **Enable Dunning** | Enables automatic payment retries. | Off |
| **Max Retries** | Maximum number of payment attempts. | 3 |
| **Retry Intervals (days between attempts)** | Number of days between payment attempts. | 3, 5, 7 |

<Tip>
  With the default settings, payments are retried after 3, 5, and 7 days. If all attempts fail, the tenant is suspended and the **Deletion Delay** starts.
</Tip>

<Note>
  **Enable Dunning** is off by default. Failed payments are not retried until you enable it.
</Note>

### Notifications

You can send reminders before a tenant's subscription expires.

<Frame caption="The Notifications card, with the expiry warning and its reminder schedule">
  <img src="/images/pa/lifecycle-notifications.png" alt="The Notifications card, with the expiry warning and its reminder schedule" />
</Frame>

| Field | Description | Default |
| ----- | ----------- | ------- |
| **Subscription Expiring Warning** | Enables subscription expiry reminders. | Off |
| **Warn Days Before Expiry** | Number of days before expiry to start warnings. | 7 |
| **Reminder Schedule (days before expiry)** | Days when reminder emails are sent. | 7, 5, 3, 1 |

<Tip>
  With the default settings, tenants receive reminders 7, 5, 3, and 1 day before expiry.
</Tip>

<Note>
  **Subscription Expiring Warning** is off by default, so reminders are not sent until you enable it.

  Tenants using auto-renewal are not included because they receive the pre-debit notice instead.
</Note>
