Every time a tenant asks the AI to build an automation, it is recorded here. You see what they asked for, what came out, and how many tokens it used.

Click **AI Flow → Generations** in the sidebar.

This is a record, not a setting. Nothing here changes how the AI behaves.

## Generation list

<Frame caption="The AI Generations log, with the prompt, status, tier and tokens for each generation">
  <img src="/images/pa/ai-generations.png" alt="The AI Generations log, with the prompt, status, tier and tokens for each generation" />
</Frame>

| Column | Description |
| ------ | ----------- |
| **Prompt** | What the tenant typed. |
| **Customer** | Which tenant asked. Empty when the generation was internal. |
| **Type** | The kind of flow they wanted. |
| **Status** | How it turned out. |
| **Tier** | How hard the AI had to work. See [Generation tiers](#generation-tiers). |
| **Tokens** | What it cost in tokens. |
| **Generated** | When it happened. |

<Tip>
  You can filter generations by **Status** and **Type**.
</Tip>

## Generation status

| Status | Meaning |
| --- | --- |
| **Success** | The flow passed the quality check. |
| **Low quality** | The flow scored below the quality bar. The tenant still got it. |

<Info>
  **Low quality** does not mean the tenant got nothing. They received a flow; it just scored poorly. A run of these is worth looking at, because it usually means your [exemplars](/pa/ai-flow-exemplars) do not cover what your tenants are asking for.
</Info>

<Note>
  The **Status** filter also offers **Failed** and **Pending**. Those normally return nothing, because a generation is only recorded once it finishes.
</Note>

## Generation tiers

The tier tells you how much work the flow took.

| Tier | What happened |
| ---- | ----------- |
| **Single** | Built once, passed. The cheapest outcome. |
| **Repaired** | The first attempt was nearly right, so the AI fixed it. |
| **Best of N** | The AI built several and kept the best one. |

<Warning>
  Higher tiers cost more. **Best of N** can use several times the tokens of a **Single** generation, so a lot of them in this column is worth investigating.
</Warning>

## View a generation

Click a generation to read the full **Prompt** the tenant sent, see the **Flow** that came out, and check the token usage.

You can also delete a generation from the list.

<Note>
  Deleting only removes this record. The flow itself stays in the tenant's workspace and keeps working.
</Note>
