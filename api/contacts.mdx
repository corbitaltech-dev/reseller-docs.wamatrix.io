The Contacts API lets you sync contacts into a client workspace from external systems — your CRM, e-commerce platform, or lead forms. All phone numbers must be in [E.164 format](https://en.wikipedia.org/wiki/E.164) (e.g. `+14155552671`).

<Warning>
  You are responsible for ensuring all contacts have given explicit opt-in consent to receive WhatsApp messages before importing them. Sending messages to contacts without prior consent violates Meta's WhatsApp Business Policy and may result in your number being restricted or banned. Always record the source and date of consent for each contact.
</Warning>

---

## GET /workspaces/{workspace_id}/contacts

List all contacts in a workspace. Supports full-text search, tag filtering, opt-in status filtering, and pagination.

### Path Parameters

<ParamField path="workspace_id" type="string" required>
  The unique ID of the workspace whose contacts you want to list.
</ParamField>

### Query Parameters

<ParamField query="search" type="string">
  Full-text search across contact name, phone number, and email.
</ParamField>

<ParamField query="tag" type="string">
  Filter contacts that have this tag applied (e.g. `vip`, `lead`).
</ParamField>

<ParamField query="opt_in_status" type="string">
  Filter by opt-in status. Accepted values: `opted_in`, `not_set`, `opted_out`.
</ParamField>

<ParamField query="page" type="integer">
  Page number to retrieve. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of results per page. Defaults to `20`. Maximum is `100`.
</ParamField>

### Request

```bash List contacts
curl -X GET "https://api.wamatrix.io/v1/workspaces/ws_01hx3g5r8f0q2k7d/contacts?tag=vip&opt_in_status=opted_in&page=1&per_page=20" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Response

```json
{
  "data": [
    {
      "id": "con_7a2b3c4d5e",
      "phone": "+14155552671",
      "first_name": "Jane",
      "last_name": "Doe",
      "email": "jane.doe@example.com",
      "tags": ["vip", "repeat-customer"],
      "opt_in_status": "opted_in",
      "created_at": "2024-05-01T09:00:00Z"
    }
  ]
}
```

## POST /workspaces/{workspace_id}/contacts

Create a new contact, or update an existing one if a contact with the same phone number already exists (upsert behavior). This makes it safe to call repeatedly from sync jobs without creating duplicates.

### Path Parameters

<ParamField path="workspace_id" type="string" required>
  The unique ID of the workspace to create the contact in.
</ParamField>

### Body Parameters

<ParamField body="phone" type="string" required>
  The contact's phone number in E.164 format (e.g. `+14155552671`). Used as the unique identifier for upsert.
</ParamField>

<ParamField body="first_name" type="string">
  The contact's first name.
</ParamField>

<ParamField body="last_name" type="string">
  The contact's last name.
</ParamField>

<ParamField body="email" type="string">
  The contact's email address.
</ParamField>

<ParamField body="tags" type="array">
  A list of string tags to apply to the contact (e.g. `["lead", "webinar-2024"]`). Tags are created automatically if they don't already exist.
</ParamField>

<ParamField body="custom_fields" type="object">
  A key-value object of custom field data to store on the contact (e.g. `{"order_count": "5", "loyalty_tier": "gold"}`).
</ParamField>

<ParamField body="opt_in_status" type="string">
  The contact's WhatsApp messaging consent status. Accepted values: `opted_in`, `not_set`. Defaults to `not_set` if omitted.
</ParamField>

### Request

```bash Create or upsert a contact
curl -X POST https://api.wamatrix.io/v1/workspaces/ws_01hx3g5r8f0q2k7d/contacts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "+14155552671",
    "first_name": "Jane",
    "last_name": "Doe",
    "email": "jane.doe@example.com",
    "tags": ["vip", "repeat-customer"],
    "custom_fields": {
      "loyalty_tier": "gold",
      "order_count": "12"
    },
    "opt_in_status": "opted_in"
  }'
```

### Response

```json
{
  "data": {
    "id": "con_7a2b3c4d5e",
    "phone": "+14155552671",
    "first_name": "Jane",
    "last_name": "Doe",
    "email": "jane.doe@example.com",
    "tags": ["vip", "repeat-customer"],
    "custom_fields": {
      "loyalty_tier": "gold",
      "order_count": "12"
    },
    "opt_in_status": "opted_in",
    "created_at": "2024-05-01T09:00:00Z",
    "updated_at": "2024-06-10T14:55:00Z"
  }
}
```

## PATCH /workspaces/{workspace_id}/contacts/{contact_id}

Update one or more fields on an existing contact. Only the fields you provide are changed; all other fields remain unchanged.

### Path Parameters

<ParamField path="workspace_id" type="string" required>
  The unique ID of the workspace.
</ParamField>

<ParamField path="contact_id" type="string" required>
  The unique ID of the contact to update.
</ParamField>

### Body Parameters

<ParamField body="first_name" type="string">
  Updated first name.
</ParamField>

<ParamField body="last_name" type="string">
  Updated last name.
</ParamField>

<ParamField body="email" type="string">
  Updated email address.
</ParamField>

<ParamField body="tags" type="array">
  Replaces the contact's existing tags with this new list.
</ParamField>

<ParamField body="custom_fields" type="object">
  Merges these key-value pairs into the contact's existing custom fields.
</ParamField>

<ParamField body="opt_in_status" type="string">
  Updated opt-in status. Accepted values: `opted_in`, `not_set`, `opted_out`.
</ParamField>

### Request

```bash Update a contact
curl -X PATCH https://api.wamatrix.io/v1/workspaces/ws_01hx3g5r8f0q2k7d/contacts/con_7a2b3c4d5e \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "opt_in_status": "opted_out",
    "tags": ["churned"]
  }'
```

### Response

```json
{
  "data": {
    "id": "con_7a2b3c4d5e",
    "phone": "+14155552671",
    "first_name": "Jane",
    "last_name": "Doe",
    "email": "jane.doe@example.com",
    "tags": ["churned"],
    "opt_in_status": "opted_out",
    "updated_at": "2024-06-11T08:10:00Z"
  }
}
```

## POST /workspaces/{workspace_id}/contacts/import

Bulk import contacts by uploading a base64-encoded CSV file. Imports are processed asynchronously — the endpoint returns immediately with an `import_id` you can use to track progress.

### Path Parameters

<ParamField path="workspace_id" type="string" required>
  The unique ID of the workspace to import contacts into.
</ParamField>

### Body Parameters

<ParamField body="file" type="string" required>
  A base64-encoded CSV string. The CSV must include a `phone` column. Supported columns: `phone`, `first_name`, `last_name`, `email`, `tags`, `opt_in_status`.
</ParamField>

<ParamField body="on_duplicate" type="string">
  How to handle contacts whose phone number already exists. Accepted values: `skip` (leave existing record unchanged) or `update` (overwrite fields with CSV values). Defaults to `update`.
</ParamField>

### Request

```bash Bulk import contacts
curl -X POST https://api.wamatrix.io/v1/workspaces/ws_01hx3g5r8f0q2k7d/contacts/import \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "file": "cGhvbmUsZmlyc3RfbmFtZSxsYXN0X25hbWUKKzE0MTU1NTUyNjcxLEphbmUsRG9l",
    "on_duplicate": "update"
  }'
```

### Response

```json
{
  "data": {
    "queued": true,
    "import_id": "imp_4f8e2a1b9c3d"
  }
}
```

<Note>
  Imports are processed asynchronously. Use `GET /imports/{import_id}` to poll for the status of your import, including the number of contacts created, updated, skipped, and any row-level errors.
</Note>
